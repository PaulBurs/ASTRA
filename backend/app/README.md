# backend/app — массовый прогноз и его взаимодействие с подготовкой данных

Описаны файлы, реализующие расчёт прогноза всех датчиков набора и исключение его
одновременного выполнения с подготовкой данных. Оба процесса нагружают один PostgreSQL.

## services/forecast_jobs.py

Очередь прогноза всех датчиков: пакеты отправляются в ML-сервис, результаты сохраняются,
расчёт можно остановить и продолжить.

| Функция / константа | Что делает | Как |
|---|---|---|
| `start_job(engine, dataset_id, sensor_ids, ml_service)` | Создаёт задачу и запускает её в фоне. Отказ, если идёт расчёт другого набора или подготовка любого набора | advisory lock PostgreSQL `LOCK_ID`; проверка подготовки после захвата блокировки |
| `_run(...)` | Выполняет задачу: пропускает уже рассчитанные датчики, держит `WORKERS` пакетов в работе, учитывает остановку | `ThreadPoolExecutor`, `wait(FIRST_COMPLETED)` |
| `_predict_batch(...)` | Пакет в ML-сервис, проверка состава ответа, атомарная запись результатов | HTTP (`httpx`), `INSERT … ON CONFLICT`, Pydantic |
| `stop_job(engine, dataset_id)` | Кооперативная остановка: начатые пакеты завершаются, результаты сохраняются | `SELECT … FOR UPDATE` |
| `latest_job`, `predictions`, `save_prediction`, `ensure_tables` | Состояние задачи (восстановление после перезапуска), результаты, схема таблиц `astra_predictions`, `astra_forecast_jobs` | SQL, JSONB |
| `preparing(engine)` | Есть ли набор в статусе `preparing` | SQL |
| `running(engine)` | Идёт ли расчёт (блокировка занята живой сессией) | `pg_try_advisory_lock` / `pg_advisory_unlock` |
| `WORKERS`, `BATCH_SIZE` | `FORECAST_WORKERS` (1–16, 4), `FORECAST_BATCH_SIZE` (1–1024, 256) | переменные окружения |

## services/dataset_import_service.py

Загрузка CSV (потоково, без временных копий), запуск подготовки
(`astra_pipeline.build_dataset`) в фоне, проверка чтения набора ML-сервисом, удаление.
`start()` помечает набор `preparing` и отказывает (HTTP 409), если идёт расчёт прогноза;
статус возвращается. Проверка выполняется после смены статуса, поэтому одновременный
запуск прогноза тоже будет отклонён. Блокировки подготовки — `fcntl.flock`.

## api/live_workspace.py

Рабочее место по подготовленному набору: датчики, карточка датчика, проверки, прогнозы.

| Маршрут | Что делает |
|---|---|
| `GET /api/datasets/{id}/forecasts` | Задача и все результаты прогноза |
| `GET /api/datasets/{id}/forecasts/job` | Только состояние задачи и флаг `preparing` (для частого опроса) |
| `POST /api/datasets/{id}/forecasts` | Запуск прогноза всех датчиков; датчики упорядочены по объекту, чтобы пакеты ML читали каждый объект один раз |
| `POST /api/datasets/{id}/forecasts/stop` | Остановка (только диспетчер) |

## api/ml.py

`GET /api/ml/predict/{sensor_id}?dataset_id=…` — прогноз одного датчика; во время
подготовки любого набора — HTTP 409.

## Тесты

`../tests/test_forecast_preparation_exclusion.py` — прогноз отклоняется во время подготовки
(блокировка освобождается, задача не создаётся); подготовка отклоняется во время прогноза
(статус набора возвращается, фоновая задача не ставится).
