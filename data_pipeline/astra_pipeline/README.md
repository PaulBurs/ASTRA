# astra_pipeline — подготовка набора данных

Пакет строит изолированную схему PostgreSQL `ds_<uuid>` из CSV-файлов организаторов:
журнал событий → очищенные события → ML-признаки (`dataset_ml`). Вызывается из
`backend/app/services/dataset_import_service.py` (`build_dataset`). Работа распараллелена
по файлам, каналам и годам; формулы признаков не дублируются, а берутся из
`../sql/03_ml_features.sql`.

## Файлы

| Файл | Что делает | Как |
|---|---|---|
| `build.py` | Оркестрация подготовки, счётчики, проверки | psycopg 3, PostgreSQL |
| `csv_input.py` | Роли CSV по заголовкам, разбор строки журнала | `csv` (stdlib), `lct_features.parse` |
| `ingest.py` | Параллельное чтение журналов в staging | `multiprocessing` (spawn), `COPY FROM STDIN` |
| `compact.py` | Дедупликация и хранение сырых/чистых событий | оконные функции SQL, декларативное партиционирование |
| `features.py` | Расчёт ML-признаков заданиями по каналам | блоки `03_ml_features.sql`, пул SQL-сессий |
| `parallel.py` | Настройки параллелизма, пул SQL-работников | `ThreadPoolExecutor`, `SET` параметров сессии |
| `registry.py` | Реестр наборов `public.astra_datasets` | SQLAlchemy Core, JSONB |

## build.py

- `build_dataset(engine, dataset_id, files, progress)` — полный цикл подготовки в схеме
  `ds_<uuid>`: staging (UNLOGGED) → справочники → очистка (`compact_events`) → признаки
  (`build_features`) → `latest_sensor_events`. Проверяет полноту справочника каналов и
  число строк признаков: все чистые события либо (при ограничении периода) чистые события
  от границы каждого канала. При любой ошибке удаляет схему целиком
  (`DROP SCHEMA ... CASCADE`), публичные таблицы приложения не затрагиваются.
- `run_script` / `execute_script` — выполнение версионированных SQL-скриптов с подменой
  схем `public.`/`ml.` на схему набора.
- `copy_references` — загрузка справочников каналов/объектов через `COPY`.
- Autovacuum заполняемых таблиц отключается на время подготовки и включается в конце
  (`set_autovacuum`): статистику подготовка собирает сама через `ANALYZE`.

## csv_input.py

- `detect_role(path)` — роль файла (`channels`, `objects`, `events`, `prepared_events`,
  `states`) по набору колонок заголовка.
- `csv_rows(path)` — чтение CSV с определением разделителя (`csv.Sniffer`), UTF-8 с BOM.
- `prepared_event(row, role)` — строка журнала → кортеж `ext_journal_prepared`:
  типизация значения (`binary`/`datetime`/`numeric`/`text`), проверки года 2019–2026,
  признака тревоги и конечности числа. Единственная точка правил разбора.
- `iter_events(path, role)` — последовательный разбор файла с номером строки в ошибке.

## ingest.py

Разбор строк в Python — узкое место импорта, поэтому файл делится на части и разбирается
несколькими процессами.

- `load_events(...)` — загружает все журналы; возвращает последнее событие каждого канала
  и множество лет. Файлы, которые нельзя делить, читаются последовательно (`iter_events`).
- `_has_quotes`, `single_line_records` — проверка, что перевод строки всегда завершает
  запись: без кавычек — сразу, иначе строгим разбором (`csv`, `strict=True`) каждой части.
  Запись, занимающая несколько строк, отключает деление файла.
- `_ranges` — части по ~64 МБ (`DATASET_IMPORT_CHUNK_MB`), выровненные по границам строк.
- `parse_chunk` — разбор диапазона байт тем же `prepared_event`; номер строки в ошибке
  совпадает с последовательным чтением (`_line_number`).
- `load_chunk` — разбор части и `COPY` через собственное соединение в процессе-работнике;
  возвращает число строк, годы и последние события канала.
- `_load_parallel` — пул процессов (`ProcessPoolExecutor`, `spawn`), остановка остальных
  частей при первой ошибке.

## compact.py

- `compact_events(...)` — создаёт `event_storage` (партиции по годам), помечает
  `is_clean` у первой из дублей (`row_number()` по каналу, времени, признаку тревоги и
  сырому значению; победитель — меньший `ид_события`) и у событий каналов из справочника.
  Задания «год × группа каналов» (остаток от деления ид канала) выполняются параллельно:
  дубли всегда внутри одного канала. После года — статистика в `build_log` и `TRUNCATE`
  staging этого года (ограничение пикового объёма диска).
- Строит индекс `(канал, время, ид_события)` и представления `ext_journal_prepared*`,
  `dataset_events*` с прежним интерфейсом чтения.

## features.py

- `feature_plan(script)` — извлекает из `03_ml_features.sql` подготовку, 32 блока
  «год × группа типов» и финальные индексы; при изменении формата скрипта — ошибка.
- `channel_batches(counts, workers)` — делит каналы блока на задания ~1 млн строк
  (`DATASET_FEATURE_TASK_ROWS`): сортировка задания помещается в `work_mem`.
- `build_features(...)` — выполняет задания в пуле, самые большие первыми; в каждом
  блоке фильтр по каналам задания, предыдущее событие ищется по `event_storage`
  (обратный индексный поиск). Возвращает число строк признаков.
- `feature_days()` — период признаков `DATASET_FEATURE_DAYS` (по умолчанию 120, не меньше
  91; `all` — вся история). Приложение читает признаки только в прогнозе (90 дней до
  последнего события датчика и соседи по объекту за 30 дней).
- Таблица `feature_cutoff` — граница канала: `min(последнее событие − DATASET_FEATURE_DAYS,
  самое раннее последнее событие в объекте − NEIGHBOUR_DAYS)`, `NEIGHBOUR_DAYS = 32`
  (720 ч соседей + 6 ч разрыва эпизода + запас). Каналы, у которых граница позже года
  блока, в блок не попадают.
- `recent_only(query)` — подменяет в блоке только границы: буфер окна и поиск предыдущего
  события — от границы канала, вывод — строки не раньше границы. Строки считаются из тех
  же событий и совпадают с полным расчётом; при несовпадении шаблонов — ошибка.

## parallel.py

- `available_cpus()` — доступные процессу ядра: привязка к CPU (`sched_getaffinity`,
  `taskset`) и квота cgroup v2 (`cpu.max`, `docker --cpus`).
- `BuildSettings` — число работников (`DATASET_BUILD_WORKERS`, по умолчанию одно на
  доступное ядро, 2–8), `work_mem` (`DATASET_WORK_MEM_MB`, 128 МБ),
  `maintenance_work_mem` для индексов (`DATASET_MAINTENANCE_MEM_MB`, 1024 МБ).
  `configure` — параметры сессии работника (без внутреннего параллелизма PostgreSQL),
  `configure_indexing` — память и до 4 параллельных процессов на построение индекса.
- `run_jobs(url, settings, jobs, work, completed)` — пул SQL-сессий; при ошибке отменяет
  остальные запросы (`conn.cancel()`) и закрывает соединения до удаления схемы.
- `set_autovacuum(conn, schema, enabled)` — `autovacuum_enabled` для всех таблиц схемы.

## Тесты

`../tests/test_ingest.py` — части дают те же строки и те же ошибки (с номером строки),
что последовательный разбор; многострочная запись обнаруживается при любой границе частей.
Эквивалентность всей подготовки старому SQL и совпадение признаков ограниченного периода
с полным расчётом (граница на краях окон 1/7/30/90 дней, замолчавший канал) —
`backend/tests/test_pipeline_equivalence.py`.
