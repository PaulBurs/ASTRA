Журнал событий датчиков инженерных систем (газ, дым, движение, двери, насосы …) за 2019-01-01 …
2026-06-30. Данные очищены, категории переведены в коды, числовые признаки нормированы
скользящим окном по истории каждого датчика. Одна строка = одно событие одного датчика (канала).

Подробное описание каждого признака, таблицы кодов и формула нормировки: features_catalog.txt.
Начните с него, этот файл — краткая выжимка.

2. СТОЛБЦЫ (22)
----------------------------------------------------------------------------------------------------
Ключи (в модель НЕ подавать):   дата_время_события, ид_канала_данных
Категориальные (коды):          код_типа_датчика (19), код_объекта (78), код_комплекса (16),
                                код_типа_значения (4), код_состояния (0..32; 0 = нет текста)
Бинарные 0/1:                   объект_охранный, состояние_техническое, тревожное_событие,
                                тревожное_по_справочнику, служебное_значение,
                                мало_истории_значение, мало_истории_dt
Циклические (время):            час, день_недели (0 = пн), месяц
                                -> sin/cos: sin(2π·час/24), sin(2π·д/7), sin(2π·(м-1)/12) и cos
Числовые:                       значение, значение_z, лог_dt, лог_dt_z, пикет

Пустые значения (NULL) осмысленны:
  значение      NULL - у события нет числа (дискретный датчик) или это служебный код ошибки
  значение_z    NULL - нет числа ИЛИ в окне < 5 прошлых точек (тогда мало_истории_значение = 1)
  лог_dt        NULL - самое первое событие датчика
  лог_dt_z      NULL - в окне < 5 прошлых событий (мало_истории_dt = 1)
  пикет         NULL - в названии датчика нет номера ПК (7% датчиков)

Какие признаки важны для каких датчиков:
  числовые (газ, температура, ИБП) - значение, значение_z;
  остальные 16 типов - код_состояния, тревожные флаги, лог_dt / лог_dt_z (ритм срабатываний).


3. НОРМИРОВКА — ВАЖНО ДЛЯ ИНФЕРЕНСА
----------------------------------------------------------------------------------------------------
значение_z и лог_dt_z посчитаны как LayerNorm по собственной истории датчика, только по прошлому:
    z_t = (x_t - mean(W)) / sqrt(var_pop(W) + eps),   W = события того же датчика в [t - L, t)
L зависит от типа датчика (1, 7, 30 или 90 дней, dicts/window_params.csv), eps - от точности
датчика (dicts/norm_params.csv). Утечки будущего нет: на инференсе те же числа даёт
inference_norm.py (StreamingNormalizer) - сверено с датасетом построчно.
Повторно нормировать эти столбцы (StandardScaler и т.п.) не нужно.


4. КАК ЗАГРУЗИТЬ (pandas)
----------------------------------------------------------------------------------------------------
Один год - до 55 млн строк, в памяти около 3-4 ГБ с типами ниже. Брать по годам или фильтровать
чанками (пример - только газ, код_типа_датчика = 2):

    import pandas as pd
    DTYPES = {
        'ид_канала_данных': 'int32', 'код_типа_датчика': 'int8', 'код_объекта': 'int8',
        'код_комплекса': 'int8', 'объект_охранный': 'int8', 'пикет': 'Int16',
        'код_типа_значения': 'int8', 'код_состояния': 'int8', 'состояние_техническое': 'int8',
        'тревожное_событие': 'int8', 'тревожное_по_справочнику': 'int8',
        'час': 'int8', 'день_недели': 'int8', 'месяц': 'int8',
        'значение': 'float32', 'служебное_значение': 'int8', 'значение_z': 'float32',
        'мало_истории_значение': 'int8', 'лог_dt': 'float32', 'лог_dt_z': 'float32',
        'мало_истории_dt': 'int8',
    }
    def load(year, sensor_code=None):
        parts = pd.read_csv(f'data/dataset_ml_{year}.csv.gz', dtype=DTYPES,
                            parse_dates=['дата_время_события'], chunksize=5_000_000)
        return pd.concat(p if sensor_code is None else p[p['код_типа_датчика'] == sensor_code]
                         for p in parts)
    gas_2024 = load(2024, sensor_code=2)

Быстрее (без распаковки в память целиком): polars.scan_csv(...).filter(...).collect()
или duckdb: SELECT * FROM 'data/dataset_ml_*.csv.gz' WHERE код_типа_датчика = 2.


5. ЗАМЕЧАНИЯ К ДАННЫМ
----------------------------------------------------------------------------------------------------
- Целевая переменная НЕ задана - её выбор за вами. Кандидаты для газа (порог тревоги по ответу
  организаторов - 1% метана): значение >= 1; код_состояния «Обнаружен газ»; тревожное_событие = 1.
  Разметки «подтверждённый инцидент / ложное срабатывание» в исходных данных нет (подтверждено QA).
- 2021 год: организаторы рекомендуют исключить (переход на новую систему мониторинга, массовые
  неснятые тревоги у датчиков дыма). В датасете он оставлен - фильтруйте сами.
- 2023 год: удалено ~614 тыс. дублей (в 10 раз больше других лет), событий меньше, чем в соседних
  годах - возможна дыра в данных.
- Валидация - только по времени (обучение раньше, тест позже); случайное разбиение даст утечку.
- ИБП: значение_z с тяжёлыми хвостами (std около 2), для линейных моделей стоит обрезать.
- Удалено при подготовке: 9,44 млн событий датчиков, отсутствующих в справочнике организаторов,
  и 0,94 млн полных дублей. Из 313,5 млн исходных событий осталось 303,2 млн.
