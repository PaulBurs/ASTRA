1. ПРИЗНАКИ
----------------------------------------------------------------------------------------------------
Категории: ключ    - служебный столбец, в модель не подаётся;
           кат     - категориальный (номинальный): код из таблицы кодов, НЕ нормируется;
           бин     - бинарный 0/1, НЕ нормируется;
           цикл    - циклический (время), кодируется sin/cos в ml.v_dataset_ml, НЕ нормируется;

3. ОЧИСТКА ЧИСЛОВЫХ ЗНАЧЕНИЙ  (ml.norm_params)
----------------------------------------------------------------------------------------------------
Число считается валидным, только если тип датчика есть в таблице ниже, значение в [мин; макс]
и не равно служебному коду. Иначе: значение = NULL, служебное_значение = 1, в окно не попадает.

тип_датчика           мин   макс  служебные коды        eps     комментарий                                                 
--------------------  ----  ----  --------------------  ------  ------------------------------------------------------------
Газовый датчик        -1    100   2.55, 10.23, 327.68   0.0001  % объёма метана, шаг 0.01; 2.55/10.23/327.68 = 255/1023/32768 делённые на 100
Датчик температуры    -50   100   -                     1.0     °C, целые; -3276…-3255 и 950…999 - служебные                
ИБП                   0     100   -                     1.0     целые 0…100                                                 

Числа у других типов (единичные записи у датчиков движения, дверей и т.п.) считаются служебными.
eps = (шаг датчика)²: у газа шаг 0.01, в спокойные периоды дисперсия окна = 0, и с eps = 1e-5,
как в нейросетях, колебание на 0.01 давало бы z ≈ 3. С eps = 1e-4 то же колебание даёт z ≈ 1.

4. НОРМИРОВКА (аналог LayerNorm: по собственной истории канала, НЕ по всей таблице)
----------------------------------------------------------------------------------------------------
Для события канала c в момент t со значением x_t:

    W(t)  = значения того же канала c с временем в [t - L ; t),  L - окно типа датчика (раздел 4.1)
            - только прошлое: текущая секунда (и другие события в эту же секунду) НЕ входят;
            - служебные / пустые значения в окно не входят.
    n     = |W(t)|
    μ_t   = mean(W(t))
    σ²_t  = var_pop(W(t))            (дисперсия по n, не n-1 - как в LayerNorm)
    z_t   = (x_t - μ_t) / sqrt(σ²_t + eps)
    если n < 5:  z_t = NULL, мало_истории = 1   (холодный старт, редкие датчики)

Применяется к двум признакам:
    значение  -> значение_z   (eps по типу датчика, раздел 3)
    лог_dt    -> лог_dt_z     (eps = 0.01); лог_dt = round(ln(1 + Δt_сек), 6),
                               Δt = t - момент последнего события канала строго раньше t
                               (события в одну секунду получают одинаковый Δt).

ОДНА ФОРМУЛА ДЛЯ ОБУЧЕНИЯ И ИНФЕРЕНСА. В ml.dataset_ml значения посчитаны так же, как их
посчитает инференс в реальном времени: модель не видит будущего, утечки нет.
Эталонная реализация для инференса: inference_norm.py (StreamingNormalizer).
Сверка SQL и Python совпала во всех строках: 845 042 события (20 дней 2024 г., 18 типов)
и 424 801 событие (выборка 2019-2026, все 19 типов, с переходами через границы лет).

Что НЕ нормируется и почему:
  - коды категорий: разность кодов смысла не имеет (5 - 3 для типа датчика);
  - бинарные флаги: уже 0/1;
  - час/день/месяц: sin/cos уже в [-1; 1];
  - пикет: статичен для канала, скользящее окно по каналу даст всегда 0.
Для линейных моделей / kNN категории подавайте one-hot по таблицам раздела 2;
для деревьев (CatBoost, LightGBM) - кодами как есть, указав их категориальными.

5. ЗАМЕЧАНИЯ ДЛЯ МОДЕЛИ
----------------------------------------------------------------------------------------------------
- 2021 год в таблице есть; по QA его рекомендуют исключать (переход на новую систему мониторинга):
  фильтр  WHERE дата_время_события NOT BETWEEN '2021-01-01' AND '2021-12-31 23:59:59'.
- В 2023 году удалено ~614 тыс. дублей (в 10 раз больше, чем в другие годы) - возможна дыра в данных.
- Газ: порог тревоги по QA - 1% объёма метана (значение >= 1). Кандидаты в целевую переменную:
  значение >= 1, состояние «Обнаружен газ», тревожное_событие = 1.
- Данные заканчиваются 2026-06-30. Валидацию делать по времени (обучение - раньше, тест - позже).
- Какие признаки несут сигнал по типам датчиков:
    числовые (газ, температура, ИБП)      - значение, значение_z, служебное_значение + общие;
    дискретные (все остальные 16 типов)   - код_состояния, состояние_техническое, тревожное_событие,
                                            тревожное_по_справочнику, лог_dt / лог_dt_z (ритм событий:
                                            частые срабатывания или долгое молчание датчика) + общие;
    общие                                 - коды типа/объекта/комплекса, пикет, час/день/месяц.
  Для дискретных датчиков «значение» всегда NULL - это нормально, их сигнал в состояниях и ритме.
